# hardware/cad/scripts/

`../*.FCStd` から図面などを生成するスクリプト置き場。FreeCAD の**コンソール版**で
動かすので GUI は不要。

## 実行

```bash
hardware/cad/scripts/fcrun hardware/cad/scripts/three_view.py
```

[`fcrun`](fcrun) が使える中で最も新しい FreeCAD を自動で選ぶ。優先順位:

| 順 | 対象 | 備考 |
|---|---|---|
| 1 | `$FREECAD_CMD` | 明示指定 |
| 2 | `~/opt/FreeCAD-*/AppRun` | AppImage を展開した場合 |
| 3 | `~/opt/FreeCAD*.AppImage` | **推奨**。ネイティブパスで動く |
| 4 | Windows 側 `freecadcmd.exe` | WSL interop 経由。`wslpath` で変換 |
| 5 | PATH の `freecadcmd` | apt 版。Ubuntu 24.04 は 0.21.2 止まり |

## スクリプト

- [`three_view.py`](three_view.py) — 3部品の**三面図**（第三角法・A4横・尺度 1:1）を
  [`../export/`](../export/) に出力する。対象は `PARTS`、構成は `LAYOUTS` で定義。
  TechDraw の HLR で稜線とシルエットを抽出し、SVG は自前で組んでいる。

### 図の構成（2種を併置）

平面図と真下の立面図は紙面の**横軸**を共有し、その立面図と右隣の図は**縦軸**を
共有する。この整列規則が平面図の前後向きを一意に決めてしまうので、「平面図の前方を
どちらに向けるか」は主投影図の選び方と同義になる。第一角法にしても各図の像の向きは
変わらない（配置だけが変わる）ので、どちらかを選ぶしかない。

| 出力 | 平面図の前方 | 主投影図 | 用途 |
|---|---|---|---|
| `<部品>-3view.svg` | **紙面上** | 背面図（−x 視点） | [`krilly-frame.svg`](../../docs/images/) と読み合わせる |
| `<部品>-3view-side.svg` | **紙面右** | 側面図（−y 視点） | 車両の一般配置図の慣例。正面図が入る |

```
layout "b"                          layout "side"
[ 平面図 上=+x 右=−y ]              [ 平面図 上=+y 右=+x ]
[ 背面図 上=+z 右=−y ][ 側面図 ]     [ 側面図 上=+z 右=+x ][ 正面図 ]
```

`b` は平面図の前方を上に固定した結果、整列できる立面図が −x 視点だけになるため
正面図を含められない。正面図が必要なときは `side` を使う。

スクリプトは以下を assert で自己検査する。

- 各図の `right` / `up` が実際に紙面の右 / 上に落ちているか
- 平面図と真下の立面図が横軸を、立面図どうしが縦軸を共有しているか
- 第三角法になっているか（平面図は elev1 の +up 側、右隣の図は +right 側の視点か）
- 図と注記・表題欄がページ内に収まり、重なっていないか

## 注意

- **`.FCStd` を書き戻さない。** スクリプトは `recompute()` / `save()` を呼ばない。
  FCStd は FreeCAD 1.1.0 (Windows) で作られており、古い版で保存すると壊れる。
  形状は保存済みの BREP をそのまま使えば正しく読める。
- **Windows 版で実行する場合の既定値に注意。** Python の既定エンコーディングが
  **cp932**、改行が **CRLF** になる。ファイルを書くときは
  `io.open(..., encoding="utf-8", newline="\n")` と明示すること（明示しないと
  図面中の日本語が文字化けする）。
- **軸のずれがある FCStd を描くとき**は [`three_view.py`](three_view.py) の
  `MODEL_TO_BODY_DEG` に Z 回りの補正角を入れる。`krilly-chassis.FCStd` は
  2026-07-25 に `Body.Placement` の Yaw=90 で車体座標系に揃えたので現在は `0`。

## 部品の組み付け位置 (2026-07-25 実測)

各部品の `Body.Placement` を下表にすると、3部品が車体座標系で正しく積み重なる。
chassis の取付穴 Ø3.0×4（58.000 × 49.000 の矩形）と middle-plate の Ø2.5×4 が
一致し、残差 0.000000mm。Z は干渉計算で決めた（接触かつ干渉ゼロになる値）。

| 部品 | Position (x, y, z) | Angle | 車体座標系での占有範囲 (X / Y / Z) |
|---|---|---|---|
| `krilly-chassis` | (0, 0, 0) | Yaw 90° | −49.968〜27.202 / ±35.135 / −47.000〜2.000 |
| `krilly-middle-plate` | (−50.468, −38.5, 17) | 0° | −52.468〜59.032 / −40.500〜40.600 / 2.000〜19.000 |
| `krilly-roof` | (−50.468, −38.5, 22) | 0° | −52.468〜59.032 / −40.500〜40.600 / 19.000〜24.000 |

検証済み（2026-07-25）:

- chassis Ø3.0×4 と middle-plate Ø2.5×4 の一致残差 **4穴すべて 0.000000 mm**
- plate↔chassis、roof↔plate はいずれも**干渉体積 0 かつ最短距離 0**（面接触）
- roof↔chassis のクリアランス 17.007 mm
- `export/*.stl` は3部品とも**配置込み**（車体座標系のグローバル座標）で書き出され、
  FCStd の bbox と一致

middle-plate と roof は Ø3.4×4 が同一座標なので XY 変換は共通。矩形パターンは
2回対称で 0°/180° の区別がつかないが、**0° だと plate 重心 x=−2.417 が chassis
重心 x=−2.305 と 0.11mm で一致**し、180° では 31.2mm 後方にずれてホイール取付半径
27.202 の外に出る（転倒する）ため 0° で確定。

## 環境の確認結果 (2026-07-25)

- Ubuntu 24.04 の apt 候補は `freecad 2:0.21.2` が上限。1.1.0 は入らない。
- 公式 Linux AppImage `FreeCAD_1.1.0-Linux-x86_64-py311.AppImage`
  (820.7MB, SHA256 `ef85f171…`) は `libfuse3` のみの環境でも直接実行できた。
- AppImage と Windows 1.1.0 の出力は**バイト単位で一致**。0.21.2 の出力とも
  ジオメトリは一致した（0.21.2 で出る `App::Point` 読み込み警告は datum point
  のみの欠落で、ソリッド形状には影響しない）。
