# 迷路データ

`Maze.from_ascii` / `Maze.to_ascii` の形式 (issue #77)。北が上、行数は 2N+1。

```
+---+---+---+
|     G     |     G = ゴール (複数書ける。外接矩形がゴール領域になる)
+   +---+   +
| S |       |     S = スタート
+---+---+---+
```

- セル幅は任意 (`+-+` でも `+---+` でもよい)。`to_ascii` は 3 文字幅で書く。
- `S` / `G` を省くと スタート (0,0) ・ゴール中央 2x2 (本番設定) になる。
- ゴールは**矩形**でなければならない (`G` の外接矩形が `G` で埋まっていること)。

## 収録

| ファイル | 用途 |
|---|---|
| `practice3.txt` | 3x3 の練習迷路。実機の `search_run --size 3` と同じ形 |
| `practice8.txt` | 8x8。**壁ちょうど 70 枚**なので手持ちで組める (#23) |
| `practice16.txt` | 16x16。解 67 セル・内壁 210 枚で、実際の大会迷路に近い密度 |

いずれも `krilly.sim.generate.random_maze` で作った合成迷路で、
`krilly.sim.check.check_maze` を通してある。

**実際の大会迷路は `contest/` にある** (2010-2024 年、31 面、#84)。
合成迷路との難易度の差もそこに測ってある — **壁の枚数を合わせても解の長さは 4 倍違う**ので、
合成迷路は本物の代わりにならない。

## 使い方

```bash
python -m scripts.maze_sim --maze mazes/practice16.txt --verbose
python -m scripts.maze_sim --maze mazes/practice8.txt --check-only --wall-budget 70
```

## 大会迷路を書き起こすとき

NTF の記録集は PDF で機械可読な形が無いので、図の画像から `scripts/maze_from_image.py`
で自動抽出する。**16x16 は壁の置き場所が 544 箇所あるので、目で写すと必ず読み違える。**
目視は「機械が出した結果が元図と合っているか」の確認だけに使う。

```bash
python -m scripts.maze_from_image <画像>... --out-dir mazes/contest
python -m scripts.maze_from_image <画像> --overlay-dir /tmp/ov   # 元図に重ねて確認
```

抽出の仕組みと検証の記録は `contest/README.md` を見ること。要点だけ:

- 壁と点線グリッドは**線に沿った平均太さ** (太さ x 連続率) で分ける。図によって
  効く手がかりが違う (太さだけ / 途切れだけ) のを 1 つの数で吸収する
- しきい値は**迷路として成立するかで自動選択**する (外周が閉じている / ゴールへ到達可能 /
  内壁が連結の上限以下)。**実際の大会迷路は必ず解ける**ので、これが強い判定器になる
- 疑わしい箇所は該当セルを拡大して目視で確認する



## 実機で組む盤面 (practice5 / excerpt8)

| ファイル | 大きさ | 壁 | 柱 | 探索手 | 最速セル | 最長直進 | **直交の補正なし** | 無壁セル | セッション |
|---|---|---|---|---|---|---|---|---|---|
| `practice5.txt` | 5×5 | 36 | 36 | 24 | 20 | 3 | **0** | 0 | 探索 45s / 最速 20s |
| `practice8.txt` | 8×8 | 71 | 81 | 16 | 16 | 7 | **2** | 1 | 探索 32s / 最速 15s |
| `excerpt8.txt` | 8×8 | 78 | 81 | 22 | 20 | 3 | **2** | 3 | 探索 42s / 最速 22s |

手持ちは**壁 80 枚・柱 85 本** (#23 で買い足し・追加製作した後)。8×8 はどんな
レイアウトでも柱 81 本が要る (`(N+1)²`)。

`practice5.txt` は**いま床に組んである迷路**で、実機の探索ランが出力した ASCII を
そのまま起こしたもの。最速経路が実測と一致する (20 セル / 12 区間 / コスト 33.5) ので、
**シミュレーションと実測を突き合わせる基準**になる。床を組み替えたらこのファイルも直すこと。

`excerpt8.txt` は 2017 年全日本エキスパート予選の (7,8) から切り出したもの (#23 / #85)。

### 「直交の補正なし」がこの表の主役

進行方向と直交する向きに壁が無いセルでは横方向の位置補正が入らず、そのぶん横に流れる。
廊下の余裕は片側 21.4mm しかないので、続くと壁に当たる。**進行方向の欠落は距離が狂う
だけで壁には当たらない**ので、危険度がまるで違う。

**5×5 はここが 0** — つまり横方向の補正が毎セル入っていた。これまで一度も試していない。

### 切り出し方

```bash
python -m scripts.maze_excerpt --size 8 --maze mazes/contest/*.txt \
    --wall-budget 80 --post-budget 85 --min-search 18 --min-cells 16 --out mazes/excerpt8.txt
```

`--min-search` は要る。直交の補正なしだけで並べると、**ゴールのすぐ隣を 6 手動くだけ**の
迷路が上位に来て探索の検証にならない (指標 1 つに最適化した典型的な失敗)。

### ゴールは競技の形にすること

窓を切り出すと、**元の迷路では普通のセルだった場所をゴールと宣言する**ことになるので、
そのままでは内側に壁が残り入口も 4 つになる。競技のゴールは **2×2 が 1 つの開いた区画で
入口は 1 つ** (大会迷路 31 面のうち 23 面が入口 1 つ、残りも 2-3 つ)。
`sim.generate.open_goal_region` / `sim.excerpt.goal_variants` が直す。

**ゴール中央の柱には壁が付かないが、それが正しい。** 実測でも大会迷路 31 面のうち 28 面が
「壁の付かない柱はここ 1 本だけ」だった。これを規則違反として数えると正しい迷路が
軒並み弾かれる (`posts_without_wall` の `ignore_goal_center`)。
