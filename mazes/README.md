# 迷路データ

`Maze.from_ascii` / `Maze.to_ascii` の形式 (issue #77)。北が上、行数は 2N+1。

```
+---+---+---+
|     G     |     G = ゴール (複数書ける。外接矩形がゴール領域になる)
+   +---+   +
| S |       |     S = スタート
+---+---+---+
```

- セル幅は任意 (`+-+` でも `+---+` でもよい)。`to_ascii` は 3 文字幅で書く。
- `S` / `G` を省くと スタート (0,0) ・ゴール中央 2x2 (本番設定) になる。
- ゴールは**矩形**でなければならない (`G` の外接矩形が `G` で埋まっていること)。

## 収録

| ファイル | 用途 |
|---|---|
| `practice3.txt` | 3x3 の練習迷路。実機の `search_run --size 3` と同じ形 |
| `practice8.txt` | 8x8。**壁ちょうど 70 枚**なので手持ちで組める (#23) |
| `practice16.txt` | 16x16。解 67 セル・内壁 210 枚で、実際の大会迷路に近い密度 |

いずれも `krilly.sim.generate.random_maze` で作った合成迷路で、
`krilly.sim.check.check_maze` を通してある。

**実際の大会迷路は `contest/` にある** (2010-2024 年、31 面、#84)。
合成迷路との難易度の差もそこに測ってある — **壁の枚数を合わせても解の長さは 4 倍違う**ので、
合成迷路は本物の代わりにならない。

## 使い方

```bash
python -m scripts.maze_sim --maze mazes/practice16.txt --verbose
python -m scripts.maze_sim --maze mazes/practice8.txt --check-only --wall-budget 70
```

## 大会迷路を書き起こすとき

NTF の記録集は PDF で機械可読な形が無いので、図の画像から `scripts/maze_from_image.py`
で自動抽出する。**16x16 は壁の置き場所が 544 箇所あるので、目で写すと必ず読み違える。**
目視は「機械が出した結果が元図と合っているか」の確認だけに使う。

```bash
python -m scripts.maze_from_image <画像>... --out-dir mazes/contest
python -m scripts.maze_from_image <画像> --overlay-dir /tmp/ov   # 元図に重ねて確認
```

抽出の仕組みと検証の記録は `contest/README.md` を見ること。要点だけ:

- 壁と点線グリッドは**線に沿った平均太さ** (太さ x 連続率) で分ける。図によって
  効く手がかりが違う (太さだけ / 途切れだけ) のを 1 つの数で吸収する
- しきい値は**迷路として成立するかで自動選択**する (外周が閉じている / ゴールへ到達可能 /
  内壁が連結の上限以下)。**実際の大会迷路は必ず解ける**ので、これが強い判定器になる
- 疑わしい箇所は該当セルを拡大して目視で確認する



## 実機で組む盤面 (practice5 / excerpt8 / excerpt8_2015 / twisty8)

| ファイル | 大きさ | 壁 | 柱 | 探索手 | 最速セル | 最長直進 | **直交の補正なし** | 無壁セル | セッション |
|---|---|---|---|---|---|---|---|---|---|
| `practice5.txt` | 5×5 | 36 | 36 | 24 | 20 | 3 | **0** | 0 | 探索 45s / 最速 20s |
| `practice8.txt` | 8×8 | 71 | 80 | 16 | 16 | 7 | **2** | 1 | 探索 32s / 最速 15s |
| `excerpt8.txt` | 8×8 | 78 | 80 | 22 | 20 | 3 | **2** | 3 | 探索 42s / 最速 22s |
| `excerpt8_2015.txt` | 8×8 | **80** | 80 | **39** | 23 | 4 | **2** | 1 | 探索 55s / 最速 20.8s (実測) |
| `twisty8.txt` | 8×8 | **80** | 80 | **61** | **45** | 3 | 1 | 0 | 探索 85s / 最速 46.0s |

手持ちは**壁 80 枚・柱 85 本** (#23 で買い足し・追加製作した後)。8×8 に要る柱は
**80 本**: 格子点は `(N+1)² = 81` あるが、**ゴール 2×2 の中央には柱を立てない**。

`practice5.txt` は 5×5 を床に組んでいたときの迷路で、実機の探索ランが出力した ASCII を
そのまま起こしたもの。最速経路が実測と一致する (20 セル / 12 区間 / コスト 33.5) ので、
**シミュレーションと実測を突き合わせる基準**になる。床を組み替えたらこのファイルも直すこと。

`excerpt8.txt` は 2017 年全日本エキスパート予選の (7,8) から切り出したもの (#23 / #85)。
**いま床に組んであるのは `excerpt8_2015.txt`** — 2015 年全日本エキスパート予選の (8,1)。

`excerpt8_2015.txt` で分かることと、分からないこと (#85):

- **探索が 39 手 (excerpt8 の 1.8 倍)。** 局所の壁パターンを踏む回数がそのぶん増える
- **進行方向 (Y) の補正なしが 5 連続** — 距離だけが狂う側の最長記録。壁には当たらないが、
  止まる位置がどこまでずれるかは実機でしか分からない
- **直交の補正なしは 2 で excerpt8 と同じ。ここは組み替えても増えない** — 壁 80 枚に
  収まる切り出し 73 件すべてが 2 以下で、9×9 は柱が 99 本要り手持ち 85 本では届かない。
  8×8 が切り出せる最大なので、**2 がこの手持ちでの上限**
- 壁を**ちょうど 80 枚**使う (予備ゼロ)。到達できないセルが 3 つある (`(0,4)` `(3,1)`
  `(4,5)`、四方壁) — 窓を切ると必ず出るもので、機体は一度も入らない

実機で確かめた結果 (2 セッション、木の床・EV 0): 5 走 238s / 25 走 1102s、中断 0 回、
**28 本の最速ランがすべて同じ経路** (23 セル / 13 区間、シミュレーションどおり)、
見積もりとの差は探索 +1.4% / 最速 −0.2%、壁判定は 306 ラベルで誤り 0・一番弱い壁が
しきい値の 3.8 倍。**探索が 1.8 倍長いこの盤面では、新しい壊れ方は何も出なかった** —
出たのはこの後で手を加えた別配置の方で、6-7 セルの廊下が区間長の上限の不在を暴いた
(#85、`speed_run --max-leg-cells`)。

### `twisty8.txt` は目的が違う — 測りたいのは「サンプル数」

`twisty8.txt` だけは**難しさで選んでいない**し、**大会迷路の切り出しでもない**。
中断の発生率は 952 動作・中断 0 回で **95% 上限 0.32%/動作**までしか絞れておらず、
下げるには走るしかない。ガードが発火するのは**コーナーを含む動作**なので、
サンプル数 = 連結動作の本数で決まる:

- 探索の動作は 1 区間ずつでコーナーが無い → **0 本**。稼げるのは復帰と最速だけ
- 束ねるのは 2 区間ずつなので、**同じセル数でも区間が細かいほど連結動作が増える**

**本物の大会迷路からは、これ以上の密度は切り出せなかった。** 実迷路は長い廊下を持つ
(30 面の最長区間は中央値 11.5 セル) ので、切り出しの最良は 27 セル / 17 区間 =
384 連結動作どまり。設計すると **45 セル / 37 区間 = 864 連結動作**まで伸びる。

鍵は**ループを作らないこと**。`DEFAULT_COST` は区間 1 本を 1.62 セル分に見積もって
曲がりを嫌うので、ループのある迷路では planner が真っ直ぐな迂回路を選んでしまう。
完全迷路 (全域木) ならゴールへの道が 1 本しかなく、**曲がりを避けられない**。
内壁は 112 の置き場所に対し全域木で 48 枚 = 外周と合わせてちょうど 80 枚になる。

25 走セッションで **864 連結動作** / 所要 39 分。**1 セッションで 952 → 1816 となり
目標の 1500 を超える**。電池を考えるなら `--max-runs 13` を 2 回 (各 20 分 / 432 本)。

**組むときの注意**:

- **壁ちょうど 80 枚で予備ゼロ。** 予備が要るなら seed 178 (79 枚 / 768 本) がある
- **壁を 1 枚でも置き間違えると経路が壊れる。** 完全迷路なので、内壁を 1 枚抜くだけで
  近道ができる — 実際このレイアウトは 1 枚余計に抜くと最速経路が 45 セルから 9 セルに
  縮む。組んだら `search_run --size 8 --dry-run` と `--truth-maze mazes/twisty8.txt`
  で必ず突き合わせること
- 「直交の補正なし」は 1、無壁セルは 0 — **横流れの検証としてはやさしい**。
  狙いがサンプル数だからで、難しさを測る盤面と混同しないこと
- 本番設定 (7 分 5 走) でも最速ランは 3 本走れるので、競技として成立しない形ではない

**生成した迷路は設計された大会迷路より易しい** (このファイルの上の方に書いてある
とおり) が、ここで測りたいのは探索でも経路計画でもなく**機構の裾**なので問題にならない。

**実機で確認済み** (本番設定 7 分 5 走、木の床・EV 0):

- 探索 87.2s (50 停止) 予測 85.4s (49 停止) → **+2.1%**、最速 45.5 / 45.6 / 45.6s
  予測 46.0s → **−1.0%**、経過 366s 予測 368s、走行 4 回 (最速 3 本) も予測どおり
- **学習した地図が真の迷路と完全一致し、しかも 64 セルすべてが「4 壁とも確定」。**
  完全迷路なので探索がほぼ全域を踏む (61 手 / 訪問 54 セル) ためで、他の盤面では
  起きていない
- **6 分のセッションで連結動作 108 本** — `excerpt8_2015` の 5 走 (48 本) の 2.25 倍。
  設計の狙いどおり
- 姿勢残差は連結 108 本で中央 0.26° / 最大 0.98° / 1.0° 超ゼロ。**中央値は他の盤面
  (0.43-0.47°) より小さいのに最大は同じ** (0.93 / 0.97 / 0.98) — #107 が
  「中央値は何も言わない、裾だけの現象」と書いたとおりの形で、**裾で数えるぶんには
  盤面をまたいで足してよい**ことの傍証になる

**25 走セッションも完走した** (2317s = 38.6 分、電池 1 本):

- 見積もりとの差は 探索 +1.9% / 最速 −1.1% / 全体 −1.1%。24 本の最速ランが
  **45.4〜45.6s** (38 分を通して幅 0.2s)、地図は 64 セルとも真の迷路と一致
- **連結動作は予測どおりちょうど 864 本**。これで累計 **1986 本・中断 1 回**となり、
  発生率は上限ではなく**点推定 0.050%/動作** (95% 上限 0.24%) になった
- **裾が初めて見えた**: 1.0° を超えた読みが **13 本 (1.5%)**、最大 **−1.79°**
  (ガードの 2.5° の 72%)。108 本のときは 1.0° 超がゼロだったが、1.5% なら 108 本で
  1.7 本の期待値なので**分布が変わった証拠にはならない** — 標本が 8 倍になっただけ。
  裾を測るには本数が要る、という #107 の教訓がそのまま出ている
  (数は目視で数えたので ±1。次からはログを `| tee` でファイルに残すこと)

### 「直交の補正なし」がこの表の主役

進行方向と直交する向きに壁が無いセルでは横方向の位置補正が入らず、そのぶん横に流れる。
廊下の余裕は片側 21.4mm しかないので、続くと壁に当たる。**進行方向の欠落は距離が狂う
だけで壁には当たらない**ので、危険度がまるで違う。

**5×5 はここが 0** — つまり横方向の補正が毎セル入っていた。これまで一度も試していない。

### 切り出し方

```bash
python -m scripts.maze_excerpt --size 8 --maze mazes/contest/*.txt \
    --wall-budget 80 --post-budget 85 --min-search 18 --min-cells 16 --out mazes/excerpt8.txt

# 2 面目。**1 位が床にあるとは限らない** — 直交の補正なしが同点 (2) なので、
# 2 位は探索の長さで選んでいる。--rank で順位を指定する
python -m scripts.maze_excerpt --size 8 --maze mazes/contest/*.txt \
    --wall-budget 80 --min-search 18 --rank 2 --out mazes/excerpt8_2015.txt

# 中断の発生率を測るための盤面。**切り出しではなく生成から選ぶ** — 本物の大会迷路は
# 長い廊下を持つので、曲がりの密度は設計した方が上がる (384 -> 864 連結動作)
python -m scripts.maze_excerpt --size 8 --generate 2400 \
    --wall-budget 80 --sort exposure --min-cells 24 --out mazes/twisty8.txt

# 選ばれたのは seed 1770。ファイルだけならこれで再現できる
python -c "from krilly.sim.generate import random_maze; \
    print(random_maze(8, seed=1770, loop_ratio=0.04).to_ascii())"
```

`--min-search` は要る。直交の補正なしだけで並べると、**ゴールのすぐ隣を 6 手動くだけ**の
迷路が上位に来て探索の検証にならない (指標 1 つに最適化した典型的な失敗)。

### ゴールは競技の形にすること

窓を切り出すと、**元の迷路では普通のセルだった場所をゴールと宣言する**ことになるので、
そのままでは内側に壁が残り入口も 4 つになる。競技のゴールは **2×2 が 1 つの開いた区画で
入口は 1 つ** (大会迷路 31 面のうち 23 面が入口 1 つ、残りも 2-3 つ)。
`sim.generate.open_goal_region` / `sim.excerpt.goal_variants` が直す。

**ゴール中央には柱が存在しない。** NTF クラシック競技規定 9:
「迷路の終点となる4区画内には壁や柱は存在しない。」

「壁の付かない柱」ではなく「柱そのものが無い」ので、**必要な柱の本数が 1 本減る**
(8×8 は 81 本ではなく 80 本)。`Maze.to_ascii` はそこに `+` を描かない — 描くと、
この図を見て組む人が立ててしまうため。実測でも大会迷路 31 面のうち 28 面で
「壁の付かない柱」がここ 1 本だけだった (`posts_without_wall` の `ignore_goal_center`)。
