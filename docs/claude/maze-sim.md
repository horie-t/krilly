# 迷路シミュレーションと迷路データ (Maze simulation & data)

生成迷路と実迷路の難しさの差、ゴール/スタートの形のチェック、迷路の切り出し (excerpt) と blind run の指標。

> CLAUDE.md から移した知見ページ。索引は [README.md](README.md)。
> 新しい知見はこのページ (または該当ページ) に追記し、CLAUDE.md には足さない。

- **A simulated maze is only as hard as you made it, and the two easy mistakes pull in opposite directions** (#77, `krilly.sim.generate`). Random mazes are generated as a spanning tree, then walls are opened to make loops; `loop_ratio` controls how many. Measured on 16×16 over 8 seeds (interior walls cap at 225): `0.0` → 225 walls, search 26–168 steps; `0.10` (the default) → 190–195 walls, 14–37 steps; `0.35` → 142–152 walls, **median 14 steps = the Manhattan minimum, i.e. the mouse never once hits a dead end**. A sparse maze is not a test of the search. But `loop_ratio=0` overshoots the other way: a DFS-carved perfect maze has the "river" property and its *own solution* ran 169 cells on a 16×16, which no competition maze does (real ones are ~40–80). Neither extreme is realistic, and **a generated maze is easier than a designed one at any density** — that is why transcribing real mazes (`mazes/README.md`) is a separate task, not a nice-to-have.
- **A generated maze is a quarter as hard as a real one, and matching the wall count does not fix it** (#84, `mazes/contest/`). Measured over 31 real All-Japan mazes (2010–2024) against 31 generated ones: interior walls 214 vs 193 — nearly the same — but the *solution* runs **59 cells vs 16**, the search **90 moves vs 21**, the speed run **77 s vs 25 s**, and the real mazes complete a median of **3 runs where generated ones always finish 5**. **Fourteen of the 31 fit no speed run at all in the 7 minutes** — the machine reaches the goal and never gets to race (that was measured before #89, #80 and the margin change; it is **3/31** now, see the `time_margin` bullet). Median runs used is 2 of 5, and exactly one maze allows all 5. Difficulty comes from where the walls are, not how many, and random generation cannot produce it at any density. But the *local* statistics do match (cells with no lateral wall 27 % vs 28 %, no longitudinal wall 28 % vs 30 %, cells with no wall at all 4 vs 5), so generated mazes are fine for exercising camera judgement and single-cell control (#85) and useless for exercising the search, the route planner, or the time budget.
- **A competition goal is one open 2×2 with one entrance, and nothing in this repo checked that until #23** (`sim/check.py`, `open_goal_region`). Both practice mazes and *every generated maze* had walls inside the goal — the generator carves the goal like ordinary cells, and an excerpt declares the centre of a window to be the goal whatever was there. Three consequences worth keeping:
  - **There is no post at the goal centre at all** — NTF classic rule 9: 「迷路の終点となる4区画内には壁や柱は存在しない。」 The code first treated it as "a post that happens to carry no walls", which gets the same answer for the wall check but the wrong answer for **how many posts to print**: an N×N with a 2×2 goal needs `(N+1)² − 1`, so the 8×8 takes **80 posts, not 81**. `Maze.to_ascii` now leaves that grid point blank, because whoever builds the maze from the drawing will otherwise stand a post there. 28 of the 31 transcribed contest mazes have exactly one "bare post" and it is always this one; `posts_without_wall` counted it as a rule violation and so flagged 30 of 31 *valid* mazes. **A rule that fails on almost all real data is a misread rule, not bad data** — and reading the actual rule text, not inferring it from the data, is what got the post count right.
  - **The same check found three broken transcriptions** (#84 data quality, recorded in `mazes/contest/README.md`): `2016_japan_freash_q` has its goal walled into four cells, `2013_japan_exp_q` is missing enough walls to leave **27 bare posts**, and `2010_japan_freash_fin` misses one. The first is pinned by a test that asserts it *fails* the check, so fixing the transcription will make that test complain.
  - **Fixing the generator moved the #84 numbers.** With a legal goal the generated 16×16s got harder (solution 16 → 20 cells, search 21 → 30 stops), so "real mazes are 3.7× harder" is now 2.95×. The conclusion is unchanged and the corpus comparison is now measured on like-for-like goals.
- **The start had the same excerpt bug as the goal, and three of the home boards carry it** (#127, `sim/check.start_openings`, `sim/generate.competition_start`). Rule 2-3 plus all 31 transcribed contest mazes (a test now pins that) put the start's single opening to the north; an excerpt declares the window's (0,0) the start whatever is there, and the generator left it at whatever degree the spanning tree gave it. `excerpt8` / `excerpt8_2015` open north **and** east, and `twisty8` opens **east only**. `check_maze` now *warns* (not errors — they are experiment boards and `maze_sim` must not fail on them) and the warning names the consequence: with `--white-tops` the start's three walls are seeded (#126), so those boards need `--no-seed-start`. `competition_start` opens north, closes the rest and reconnects anything stranded through a non-start wall; `random_maze` applies it by default (`fix_start=False` reproduces pre-#127 seeds — `twisty8` and the #87 margin test are pinned that way, and the latter's seed-5 maze became *easier* with the start fixed, finishing in 202 s instead of overrunning) and `goal_variants` applies it to every excerpt, so `maze_excerpt --out` now writes a competition-shaped start — i.e. **it no longer reproduces `excerpt8*.txt` byte for byte**. Whether to rebuild the board on the floor is a separate decision.
- **The cross-blind run is pinned at 2 by the wall stock, so the second board buys search length, not sideways blindness** (#85, `mazes/excerpt8_2015.txt` = 2015 All-Japan expert qualifier, window (8,1)). Every one of the 73 excerpts that fits in 80 walls scores `blind_cross ≤ 2`, and a 9×9 window needs **99 posts against a stock of 85**, so 8×8 is the largest buildable window and 2 is the ceiling — **no rebuild improves the metric #85 is named after.** What the 2015 board adds over `excerpt8.txt` is 39 search moves against 22 (1.8×), a 5-cell run with no *along-track* correction (distance drifts, nothing collides) and a 4-cell straight; it costs **exactly 80 walls, i.e. the whole stock with no spare**, and seals 3 cells the machine never enters. Note the ranking's top entry is the board that was already on the floor, so `--out` alone reproduces the *old* one — `--rank 2` is what writes this one.
- **"No position correction here" comes in two kinds, and only one of them ends a run** (#23/#85, `sim/excerpt.py`). A cell with no wall on an axis gives no red band there, so that axis cannot be corrected. But the consequence depends on which way the machine is *travelling*: missing the **along-track** axis only makes the distance drift (the machine stops in the wrong place and the next perpendicular wall fixes it), while missing the **cross-track** axis makes it drift sideways, and the corridor only allows 21.4 mm per side. `longest_blind_cross_run` counts consecutive route cells with no cross-track correction; that is the number to maximise when choosing a maze to build. Ranking by the naive "no correction on either axis" instead put a **6-move maze right next to the goal** at the top — a single metric optimised without the physics behind it.
- **The 5×5 has never once run blind sideways, and the synthetic 8×8 barely does either** (#23). Measured with `scripts/maze_excerpt.py`: `practice5` — 24 search moves, 20-cell route, **cross-blind run 0, no wall-less cells**; `practice8` (synthesised) — 16 moves, 16 cells, cross-blind 2, 1 wall-less cell; the chosen `excerpt8` (2017 All-Japan expert qualifier, window (7,8)) — 22 moves, 20 cells, 15 legs, cross-blind 2, **3 wall-less cells**, 78 walls and 80 posts against a stock of 80 and 85 (`maze_excerpt` printed 81 until #85 — it was listing grid points, and the goal centre carries no post). So building the existing 8×8 would have tested *less* than the maze already on the floor, and the only way to get a cross-blind run is to cut one out of a real maze. `mazes/practice5.txt` records the 5×5 as it stood on the floor (the board there is now the 8×8) — its shortest path reproduces that hardware run exactly (20 cells / 12 legs / cost 33.5), which is what makes it the reference for checking the simulator against reality.
