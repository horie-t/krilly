● 結論

  今わかっている範囲では、本番の迷路でも起きる可能性は高く、条件しだいで壁に当た
  る大きさになると見ています。ただし、そう言える根拠のうち「迷路の歪み」の部分は
  、本番の迷路にそのまま当てはまるかどうか分かっていません。確度の違う 2
  つの要素に分けて説明します。

  1. 本番でも起きると考える理由

  (a) 原因がまだ説明しきれておらず、その部分は機体側の可能性がある
  - (3,6)→(6,6) の東 3 セルは、F3 / D3 の単発テストでは南へ約 5mm
    でした。同じ区間が speed_run では 11〜14mm ずれています。
  - 差の 6〜9mm が「走る前の補正を北の壁 1
    枚で読んでいた」ことによるのか、それまでの動作の影響なのか、まだ切り分けてい
    ません。迷路の歪みでなければ、この分は迷路を替えても残ります。

  (b) 会場の 16×16 (2026-10-17 の交流会) でも同じ種類の現象が出ている
  - 上の行を東西に走ると、3 セルで +24 → +14 → +12mm ずれました。6 セルつなげた
    N3->E3 では、着いたセルが 10〜18mm ずれています。
  - Issue のコメントにも「会場の迷路では東へ進むと北へ」と書かれています。向きは
    自宅の迷路と逆です。

  2. 本番の迷路にそのまま当てはまるか分からない点

  (a) 自宅の迷路の「約 0.5° の歪み」は、3D プリントの柱で自立させた壁 (#65) 
  の特性かもしれない
  - この迷路は縦横の間隔がもともと 1.5%
    違います。土台の溝に壁を差す、作りのしっかりした迷路なら、歪みはもっと小さい
    はずです。ただし、本番の迷路の精度は一度も測っていません。

  (b) 会場のデータは条件が混ざっていて、きれいに分けられない
  - あの時点では camera_yaw_offset_deg も合っていませんでした (0.1 → −0.35)。
  - 4 方向の 3 セルのずれは D3 9.0 / A3 1.8 / F3 6.0 / B3 9.6mm でした。迷路が一
    様に歪んでいるなら東と西のずれは同じ大きさに、機体の向きのずれやクラブなら 4
    方向とも同じになるはずです。東と西 (9.0 と 1.8) が違うので、どちらの説明に
    も合いません。考えられるのは、場所ごとに違う局所的な歪みか、測定のばらつき
    (各 1 回) です。
  - しかも、−0.35 は上の行の東西のずれを消すように合わせた値です。会場の迷路の歪
    みの一部を、機体の定数として吸収してしまった可能性があります。

  3. 実害が出る条件

  止まると毎回カメラで位置を補正するので、ずれが溜まるのは止まらずに走る区間の中
  だけです。

  ┌────────────────────────────┬──────────────┬────────────────┬────────────┐
  │    止まらずに走るセル数    │ 3〜4mm/セル  │  2〜3mm/セル   │ 通路の余裕 │
  │                            │    (自宅)    │  (会場の実測)  │            │
  ├────────────────────────────┼──────────────┼────────────────┼────────────┤
  │ 3                          │ 9〜12mm      │ 6〜9mm         │ 21.4mm     │
  ├────────────────────────────┼──────────────┼────────────────┼────────────┤
  │ 6 (交流会の設定            │              │ 10〜18mm       │            │
  │ --max-leg-cells 3 ×        │ 18〜24mm     │ (実測)         │ 21.4mm     │
  │ --chain-legs 2)            │              │                │            │
  ├────────────────────────────┼──────────────┼────────────────┼────────────┤
  │ 8 (今の既定 4 × 2)         │ 24〜32mm     │ 16〜24mm       │ 21.4mm     │
  └────────────────────────────┴──────────────┴────────────────┴────────────┘

  - 探索ではほぼ問題になりません。 ほぼ毎セル止まって補正するためです。
  - 危ないのは最速走行の長い区間です。 16×16 では 8
    セル続く区間が実際に出てきます。今の既定値のままだと、自宅と同じ程度のずれで
    も余裕を超える計算になります。交流会の 6 セルでも、すでに余裕の 8
    割まで来ていました。

  見立てのまとめ

  - 現象が出るか: 高い。会場で出ており、機体側かもしれない分も残っています。
  - ずれの大きさと向き: 迷路ごとに違うので、自宅で合わせた値は使えません。
  - 衝突まで行くか: 今の既定値 (最大 8 セル止まらない)
    のままなら、あり得ると見ています。止まらない区間を 3
    セル程度に抑えれば、余裕の中に収まる見込みです。

● Issue #168 (https://github.com/horie-t/krilly/issues/168) を作り、対応を PR
  #169 (https://github.com/horie-t/krilly/pull/169) にしました。単体テストは 831
  本すべて通っていますが、実機ではまだ試していません。マージはお任せします。

  原因の見立て

  停止時の位置補正は、南北と東西で別々に入ります。

  - 南北の位置は、そのセルの北か南の壁で測ります。
  - 東西の位置は、東か西の壁で測ります。

  東西に続く廊下の途中のセルには、北と南の壁しかありません。そのため、何度止まっ
  ても横 (南北) は補正されますが、進行方向 (東西) は一度も補正されません。前進は
  1 動作で約 10mm 行き過ぎるので
  (#164、物差しで確認)、角に着くころにはずれが積み上がっています。

  試走会のログ logs/run_20260926_153016.log
  にも同じ形の接触がありました。復帰経路で東へ 8 セル進んだ後の角 (Eへ4->Nへ1)
  で、指令していないのに 6.96° 回っています。ただ、この時点では停止ごとの補正量
  をログに出していなかったので、ずれの大きさまでは確かめられません。

  対応

  - 南北と東西のそれぞれについて、「その方向に動いたのに補正できなかった停止」を
    数えます。
  - その回数が上限 (既定 2) に達したら、経路の先で最初にその軸を補正できるセルで
    必ず止まります。北側の廊下なら、角のセルに東の外壁があるので、そこで止まって
    東西を補正してから曲がります。
  - 補正できるかどうかは、地図 (確定した壁) から判断します。白・黄の壁で補正でき
    なかったセルは、どちらの軸も補正できないものとして扱います。
  - 実機と見積もりが同じ分け方を使うので、増えた停止の時間も予算判断に入ります。
  - speed_run / maze_sim に --max-unfixed-stops を追加しました。0
    にすると今までどおりの動きです。
  - 足した停止は、speed_run のログに「補正のため停止 (#168): (x, y)
    で東西を補正してから進む」と出ます。

  効果と代償 (大会迷路 31 面、上限 2)

  - 補正できない停止が 3 回以上続いたまま曲がる箇所は、104 → 28 に減りました。
  - 代償は、最速ラン 1 本あたり平均 +2.1s (最大 +6.0s) です。31
    面合計の最速ランの本数は 38 → 37 で、1 本減ります。

  上限を 1 にすると最速ランが 4 本減り、3 にすると減りませんが補正しないまま曲が
  る箇所が多く残ります。そのため、間を取って 2 にしました。

  残る 28 か所は、角に進行方向と直交する壁が無いところ (T 字路・十字路) です。
  壁の帯だけでは補正できないので、この変更では防げません。柱や格子の位相を使えば
  補正できる見込みはありますが、まだ実装していないので、別の課題として扱うのがよ
  いと思います。

  実機で確かめてほしいこと

  長い廊下のある盤面で speed_run を走らせて、次の 3 点を確認してください。

  1. ログに「補正のため停止 (#168)」が出ること。
  2. その停止の「停止 (x, y): … 位置ずれ
     実測」の行に、進行方向の補正量が出ていること。
  3. 角を曲がれること。

  自宅の 8×8 では廊下が短いので、上限 2 に届かないかもしれません。その場合は
  --max-unfixed-stops 1 にすれば、短い廊下でも働くことを確かめられます。

  今の Pi の状態

  - 有線 (eth0) はリンクが上がっています (UP) が、IP
    がありません。今ある有線の設定「Wired connection 1」が DHCP
    待ちになっていて、PC と直結した状態では誰も IP を配らないためです。

  1. Pi 側 (Pi のターミナルで)

  直結用の設定を、今の有線の設定とは別に作ります。

  sudo nmcli con add type ethernet ifname eth0 con-name pc-direct \
    ipv4.method manual ipv4.addresses 192.168.50.2/24 ipv4.never-default yes \
    ipv6.method link-local connection.autoconnect-priority 10
  sudo nmcli con up pc-direct
  ip -br addr show eth0      # 192.168.50.2/24 が出れば OK

  - ipv4.never-default yes を付けているので、有線がインターネットへの出口を横取
    りしません。インターネットには、これまでどおり Wi-Fi で出ます。
  - 192.168.50.x は、家の LAN (192.168.1.x) や WSL
    の内部ネットワークと重ならないように選んだ番号です。
  - 優先度を 10 にしたので、ケーブルを挿すたびにこの設定が使われます。家のルータ
    ーに有線でつなぎたいときは、sudo nmcli con up "Wired connection 1" で DHCP
    の設定に切り替えてください。

  設定 → ネットワークとインターネット → イーサネット → IP 割り当て の「編集」
  を開き、次のように入れます。

  - 手動、IPv4 をオン
  - IP アドレス: 192.168.50.1
  - サブネットマスク: 255.255.255.0
  - ゲートウェイ・DNS: 空欄

  ゲートウェイを入れると、Windows
  がそちらからインターネットに出ようとしてしまうので、空欄のままにしてください。

  ping -c 3 192.168.50.2
