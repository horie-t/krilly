# 会場での走行手順 (issue #78)

競技会場で走らせる当日の手順。**練習室と会場で変わるのは照明と床**で、そのどちらも
カメラの壁判定に直接効く。ここに書いてあることは全部、実機で測った結果に基づく
(根拠は CLAUDE.md の該当項目を参照)。

判断に使う数字は 2 つだけ:

- **暗さへの余力 [段]** — 起動直後の 1 行に出る。走らせる前の判断に使う
- **余裕倍率** — 一番弱い壁 ÷ しきい値。走った後の判断に使う (`survey_report`)

---

## 走らせる前

### 1. バッテリ残量を **LED で** 確かめる (電圧計では分からない)

電源は Geekworm X-UPS1 (18650 x4)。**L6470 の VS も Pi もここから取っている**
(12V/3A と 5V/3A は別々の上限)。基板の緑 LED 4 個が 25 / 50 / 75 / 100 % を示す。

**LED 4 つ (満充電) で始めること。** 効くのは**開始時の充電状態だけ**で、
5 走のセッションは弱ったパックを炙り出す負荷ケースになる。

**電圧を測っても残量は分からない。** X-UPS1 の 12V 出力は**安定化されている**ので、
電池が満充電でも半分でもほぼ 12V を返し、保てなくなったところで落ちる。
ここには以前「満充電で 12.17V」と書いてあったが、それは電池ではなく
**レギュレータの出力**を測っていた。「204 秒のセッションで 12.17 → 12.18V と
ほとんど下がらない」という測定結果自体が、安定化されている証拠になっている
(生のリチウムパックをモーターで 204 秒引いて下がらないということはない)。

**残量をソフトから読む手段は無い。** I2C の残量計は載っておらず、基板が出しているのは
LBAT (セル電圧 ≤ 3.0V で High) と PLD (外部電源断) の GPIO だけ。**LBAT は遅すぎる** —
リチウムセルの 3.0V はほぼ空で、滑りはそのずっと手前から始まる。目視の LED が指標。

弱ったパックは滑る。**L6470 のフォールトは出ず** (BEMF の脱調検出はこの速度では鈍い)、
**残差も出ない** (odometry は指令速度を積分するので、滑っても推定は理想どおり進む)。
つまり**ログを見ても分からない**。気づく手段は 2 つだけ:

1. **走らせる前に LED を見る** ← 確実
2. **異音を聞く** — 走行中に届く唯一の症状。ただし**擦れる音の原因は 4 つあって、
   パックはその 1 つに過ぎない。**

   ここには以前「#87 の測定で実際に起きた」例を挙げていたが、**あの帰属は誤りだった**:
   異音 + 進行方向に 27mm 足りない + 残差 0.4mm は事実だが、**パックは 12.17V で満充電**で、
   操作者も接触を見ていない。真の原因は**床板 (市販の競技用床) の撓みが機体底に接触**して
   いたことで、バッテリ位置を下げ・スペーサーを増やして解決した。
   **この 1 つの事象が「壁を擦った」→「電池が弱った」→「床板」と 3 回診断し直されている。**
   だから**「前にも聞いた音だ」で決めないこと。**

### 擦れる音がしたときの切り分け順

1. **LED を見る** — 4 つ点いていれば電源ではない
2. **接触を見ていたか** — 操作者が見ていて壁に触っていなければ、擦ったのではない
3. **前進と後退を聴き比べる** — `cell_move_demo --seq F4` と `--seq B4`。前進と後退は
   **同じ 2 輪を同じ輪速で回す** (W1 355 / W2 344 step/s、符号が反転するだけ) ので、
   **片方向だけ鳴るなら電源でもトルクでもなく機械**。#103 はこれで見つかった —
   ローラーのゴムが芯より長く、軸方向に押されるとホイールのプレートに擦れていた。
   机上の判定は**手でローラーを片側に寄せて回す** (= ホイールが進行方向に対して斜めの状態)
   — 固ければそれ
4. **床で切り分ける** — 黒い床で鳴って木の床で鳴らないなら、板の撓み

4 原因の対照表は CLAUDE.md の「An audible rub has had four different causes」。

### 2. 迷路の周囲 1 セルぶんを片付ける

960x720 では画角が **3.15 x 2.33 セル**あり、迷路の外に置いた赤いものが写る。
実際に、迷路の東に置いた赤い定規袋が `right:right` に 0.97 と出て、
その場所で軸角の補正が棄却された。

### 3. スタートセルに置いて、会場の照明の下で起動する

**露出と AWB は起動 0.5 秒後にロックされる。** つまり 1 回の走行は「起動した瞬間の光」に
焼き付けられる。

- 廊下で起動して運び込むのは、**別の光でロックすること**になる
- 起動の瞬間に人が機体の上に影を落とすと、1 走行まるごと狂う
- 照明が変わったら、撮り直しではなく**スクリプトの再起動**が要る

### 4. 当日はボタンで走らせる (#79)

会場ではネットワーク越しに操作できないので、**前日の試走で走らせて良かったコマンドを
保存しておき、当日はボタンで走らせる**。

**前日 (試走会、SSH できるうちに)**:

```bash
sudo systemctl stop krilly-launcher          # GPIO を取り合うので止めておく
python -m scripts.speed_run --size 16 --ev -2 --white-tops --save-run-config
python -m scripts.launcher --check           # 当日走るコマンドを表示する
sudo systemctl start krilly-launcher
```

`--save-run-config` は**完走したときだけ**書く (中断したコマンドは保存されない)。
`--check` の出力で **EV と `--white-tops`** を必ず見ること — 木の床 (EV 0) の設定を
黒い床へ持ち越すと、後方の壁を見落とす (#100)。

**当日**:

| 操作 | 音 | 意味 |
|---|---|---|
| 電源を入れる | ピッ | 起動した (設定が読めないと **ピピピピピ**、そのときは走れない) |
| 1 秒押して離す | ピッ (1 秒) → ピッ ピッ ピッ ピー | 3 秒後に発進。**カウントダウンの間に手を機体の上からどける** (露出と AWB は走行プロセスの起動時にロックされる。影が落ちると 1 走行まるごと狂う) |
| カウントダウン中に押す | ピピ | 取り消し |
| 走行中に押す | ピー | 停止 (Ctrl-C と同じ経路) |
| — | ピピピッ | 完走 |
| — | ピー ピー | 中断 (安全チェックが止めた等) |
| — | ピピピピピ (繰り返し) | **走行プロセスが止まらない。VS 遮断のトグルでモータを止める** |
| 待機中に 5 秒押し続ける | ピー (1 秒) | 電源を切る (SD カードを守る) |

走行ごとの出力は `logs/run_<日時>.log` に残る。

## 起動直後の 1 行を読む

```
露出をロック: 32.7ms (フレーム間隔の上限) / ゲイン 3.51 (上限 16.0、残り 2.2 段)
```

**「残り N 段」が暗さへの余力**。1 段 = 明るさが半分になっても保てるという意味。
露出は 30fps 固定で頭打ちになるので、暗さに対抗しているのは実質ゲインだけ
(実測: 調光 100/30/5% で露出は 32.7ms のまま、ゲインが 2.16 → 6.21 → 10.67)。

| 残り | 判断 |
|---|---|
| **2 段以上** | 余裕。そのまま走らせる |
| **1〜2 段** | 走らせてよい。走行後に `survey_report` で余裕倍率を確認する |
| **1 段未満** | 警告が出る。下の手順へ |

### 警告が出たら: `--max-frame-duration 100` を付けて再起動する

```bash
python -m scripts.speed_run --size 16 --max-frame-duration 100
```

露出の上限が 33.3ms から伸び、**0.6 段ぶん**暗さに強くなる (実測: 露出 32.7 → 50.0ms、
ゲイン 3.51 → 2.29)。代償は 1 停止あたりの待ち時間だけ — 壁の撮影は必ず停止中に
行われる (移動 → 惰行 → 撮影) ので、走行中のブレは判定に入らない。

**100 より大きい値に意味は無い。** libcamera の AE が 50ms で露出を打ち切り、
その先はゲインに回すため、200 でも 400 でも結果は同じだった。

### それでも警告が出るなら

設定でできることは終わり。**照明が足りない。**

1. 運営に照明を上げられないか相談する
2. 上げられないなら、その照度で走ることを覚悟したうえで、まず
   **`--dry-run` か `wall_detect --measure 5`** で赤割合を見る (走らせずに確認できる)
3. 弱い壁が 0.20 を割っているようなら、走らせれば壁を倒す公算が高い

> **しきい値を下げて凌ごうとしないこと。** 進路チェックが同時に鈍り、
> 「壁検出をすり抜けたものを進路確認が拾う」という二重の防護が一重になる。
> #88 で実際にそれが起き、本物の壁 0.24 が検出 (0.25) と進路確認の両方を
> 0.01 差ですり抜けて壁を突き破った。

## 黒い床では `--ev -1` を付ける

**会場の床は黒い。** 視野の大半が黒いと AE が開き (ゲイン 3.3 → 7.1)、**後方の壁の帯だけが
淡くなって彩度が `s_min` を割る**。実測 (#100、市販の競技用床): back の赤割合が
**0.46 → 0.13** — しきい値 0.08 の 1.6 倍しかなく、#88 で壁を突き破ったときの 0.24 より低い。
front / left / right は 0.40-0.45 のまま変わらないので、**back だけを見ること**。

対策は **`--ev -2`** (AE の目標を 2 段下げる)。露出時間の決め打ちと違い、会場の明るさに追従する。

廊下の東端 (悪い方) での実測:

| | ゲイン | back | 帯の彩度 |
|---|---|---|---|
| EV 0 | 8.33 | **0.09** | S 42 (帯の 80% が s_min 割れ) |
| EV -1 | 3.94 | **0.17** | S 42 (69%) |
| **EV -2** | 2.00 | **0.53** | S 64 (26%) |

**EV -1 では足りない。** 西端では 0.48 まで戻るが、東端では 0.17 止まりで、
しきい値 0.08 の 2 倍しかない。-2 まで下げて初めて 0.53 (6.6 倍) になる。

front / right は EV をいくつにしても 0.42-0.46 で動かない (明度は下がるが彩度が
上がるため)。**下げて失うものは無く、back の余裕だけが戻る。**

**ただし -3 以下にはしないこと。** EV -2 の時点で back の帯の 20% が既に `v_min=40` を
割っている (EV -1 では 0%)。s_min の崖と v_min の崖の間で、-2 がその真ん中。

`--ae-constraint Highlight` は効かない (0.5 段しか戻さず back は 0.11 のまま)。

**どの辺が弱くなるかは照明の位置で決まる。** 機体の後ろの壁が天井灯を鏡面反射する
角度に来るので、この部屋では back だった。会場では別の辺かもしれないので、
**4 辺すべてを見て、一番低い辺で判断すること。**

### 手順

1. `--measure 5` を素で撮り、**4 辺の中で一番低い赤割合**を見る
2. 0.30 以上 → そのままでよい
3. 0.30 未満 → `--ev -1` で再測定 → まだ低ければ `--ev -2`
4. `--ev -2` でも戻らなければ、帯が淡いのではなく**暗すぎる**可能性がある
   (ゲインの残り段数を見る)。その場合は EV を戻して `--max-frame-duration 100`

## 黒い床では `--white-tops` も付ける (#125)

競技規定 2-1 で、**始点の区画と終点領域の区画の壁の上面は赤・白・黄のどれでもよい**。
赤しか見ないと、ゴールの境界の壁 7 枚が全部「開」と読まれ、最初にゴールへ近づいたときに
白い壁へ突っ込む。進路確認も「見えた壁で止まる」検査なので、見えない壁は止められない。

`--white-tops` で白・黄の帯も壁として読む。**`--ev -2` と組で付ける** (どちらも黒い床の設定)。

```bash
python -m scripts.speed_run --size 16 --ev -2 --white-tops
```

- **木の床では付けないこと。** EV -2 では木の床が全面「黄」と判定される (実測)
- 白・黄の帯は**壁の有無と進路確認にだけ**使い、位置補正には使わない。始点・終点では
  その軸の位置補正が効かないだけで、走行は続く
- `wall_detect --measure 5 --ev -2 --white-tops` の出力で、白・黄で拾った辺には `w` が付く
- `--white-tops` を付けると**始点の 3 壁 (前以外) を規定 2-3 から地図に書き込む** (#126)。
  始点が規定の形でない自宅の盤面 (excerpt8 系・twisty8) で黒い床を使うときは `--no-seed-start`

**試走で確かめること** (会場でしか分からない): 本物の始点・終点の上面が白か黄か、
どの辺がそうか、その明るさ。探索ランを `--save-frames` 付きで 1 本走らせれば全部撮れる。
手元の実測は**白・黄 0.446 以上に対して壁なし 0.002 以下** (しきい値 0.08)。**白の彩度は
ホワイトバランスのロックで動く** (同じ白い壁が S 6-39 のことも S 64-73 のこともあった)。会場の白が
つや消しか光沢か、床の光沢がどこに出るかで変わりうるので、`w` の付いた辺の値を見ること。

## ちらつきの確認 (水銀灯の会場では必須)

体育館の水銀灯は 100/120Hz で明滅する。露出は固定なので、フレームによって
明るさが変わりうる。**静止しているのに値が動けばそれ**:

```bash
python -m scripts.wall_detect --measure 5
```

「静止中のばらつき」の幅が 0.0mm から動くか、赤割合がフレーム間で振れるかを見る。
練習室の LED (NLEH08002E-LC) では幅 0.00 / 軸角のばらつき 0.086° で、ちらつきは無かった。
**会場でちらついたら**、露出時間を 1/50 秒の整数倍 (10ms / 20ms) に固定するのが対策
(現状そのオプションは無いので、その場では `--max-frame-duration` で露出を動かして
振れが減る点を探すことになる)。

## 走った後に読む

会場の迷路は形が未知なので `--truth-maze` は使えない。ラベルは走行後に確定した
地図から貼られる:

```bash
python -m scripts.search_run --size 16 --save-frames survey/venue/run
python -m scripts.survey_report survey/venue/run_labels.csv --sweep
```

**読むのは誤判定の数ではなく余裕倍率。** 学習地図で貼ったラベルでは
「毎回見落としている壁」が壁なしと記録され、誤判定 0 に見えてしまう。

| 余裕倍率 | 意味 |
|---|---|
| **5 倍前後** | 練習室と同じ。健全 |
| **2〜3 倍** | 走れるが、壁が 1 枚傾いただけで落ちうる |
| **1.5 倍以下** | 危険。#23 では誤判定 0 のまま 1.4 倍まで落ちていた |

### 余裕が足りないと分かったら

**触るのはしきい値ではなくマスク。** 保存したフレームに対して、追加の走行なしで
その場で決められる:

```bash
python -m scripts.wall_detect --batch survey/venue --weak 5      # なぜ弱いのか (色相? 彩度?)
python -m scripts.wall_detect --batch survey/venue --h2-lo 120    # 変えたらどうなるか
```

`--weak` が「取りこぼしの主因」を名指しする。`--batch` を色相や彩度を振りながら回し、
**壁側だけが上がり壁なし側が動かない**範囲を探す。壁なし側も一緒に上がるなら、
それは壁ではない何かを拾い始めている。

実際にこの手順で `h2_lo` を 140 → 125 に直した (所要 10 分、走行は確認の 1 回だけ)。
そのとき一番淡い壁は 6500K の明るい照明下で **0.046** — しきい値 0.08 を下回っており、
**見落とし = 衝突**だった。

## 走行中

- **ボタンで起動したときは、止めるのもボタン** (押した瞬間に SIGINT)。止まらなければ
  **VS 遮断のトグル**。SSH から走らせたときは Ctrl-C
- **止めるのは Ctrl-C。ESC は効かない** (これらのスクリプトはキー入力を読まない)。
  強制終了してモーターが回り続けたら `python -m scripts.motor_stop`
- 走行中止を自分から申し出ると、**規定 3-5 により迷路の記憶を全消去**した場合にのみ
  認められる (異常が審判に明らかな場合を除く)。赤割合 0.09 での安全停止は
  「あきらかに走行に異常」とは読まれない公算があり、そのとき探索は失われる。
  一方、規定 3-1 では記録は**最速の 1 走行**なので、最速ランが時間切れになっても
  失うのは時間だけ。**迷ったら止めずに走らせる**
